## 2. 目标边界（v0.3.1 结束时）

```text
PlaybackService（目标 ≤ 400 行）
  ├─ 生命周期：onCreate/onGetSession/onDestroy/onTaskRemoved
  ├─ singlePlayer（ExoPlayer）构建与 listener
  └─ 委托：
       ├─ EqHost              （EQ 挂载/重试/快照/命令）
       ├─ SnapshotPublisher   （通知/UI 快照推送）
       ├─ MultiTrackCoordinator（多轨状态 + load/exit/音量/焦点）
       └─ PlayerCommandHandler（onCustomCommand 分派）
```

**不做**：改 `MultiTrackController`/`StemMixer`/`AudioSink`；改命令协议（`MultiTrackSession.CMD_*` 常量不动，避免 UI 侧联动）；改线程模型（仍 `multiIo` 单并发 + 主线程 handler）。

## 3. 分步计划

每步：改 → `compileDebugKotlin` → `testDebugUnitTest` → `lintDebug` → 真机 smoke → 独立 commit。

### Step 1 · `EqHost`（✅ 已完成，v0.3.1 进行中）

迁移成员：`eqController`、`attachSingleEq`、`attachMultiTrackEq`、`eqRetry`、`cancelEqRetry`、`eqSnapshotJson`、`handleSetEqEnabled`、`handleSetEqBand`、`handleResetEq`、`handleApplyEqTestCurve`、`handleApplyEqDefaultCurve`。

- 构造注入：`Context`、`Handler`、`audioSessionId` 提供者、快照请求回调。
- Service 保留同名 private 方法做 thin delegate，调用点零改动。
- 验收：真机 EQ 开/关、频段拖动、重置、单轨/多轨切换后 EQ 仍生效；`eqSnapshotJson` 内容不变。
- 实测：`PlaybackService` 896 → **838 行**；真机 EQ 全路径通过（单轨挂载/开关/频段/多轨重挂/退出恢复）。

### Step 2 · `SnapshotPublisher`（✅ 已完成）

迁移：`requestSnapshotPush`、`snapshotRunnable`、`progressRunnable`、`pushTracksSnapshot`、`snapshotRunnable`。

- 构造注入：`MediaSession` 提供者、多轨快照提供者（tracks json/uri/title/speed/pitch）、EQ 快照提供者。
- `progressRunnable` 的 200ms 节奏、`Bundle(session.sessionExtras)` 合并语义（P2-5）必须原样保留。
- 验收：通知标题/播放态、锁屏、UI `extras` 快照、多轨进度位置不变。
- 实测：`PlaybackService` 838 → **800 行**；真机多轨进度 `0:05→0:11` 前进、EQ 快照命令正常、`exitsmt` 正常。

### Step 3 · `MultiTrackCoordinator`（核心，分 3 小步）

> 命名：`player/MultiTrackSession.kt` 已是承载 `CMD_*`/`KEY_*` 协议的 `object`，
> 新类不能同名 → 用 **`MultiTrackCoordinator`**（不用 Host，避免与 Android Service 混淆）。

**3a · 字段搬家 + alias（不迁方法，最低风险）**
- 把字段定义移到 `MultiTrackCoordinator`：`current`/`active`/`io`/`loadJob`/`loadPending`/`loadGen`/`originalUri`/`originalTitle`/`audioAttributes`/`focusHeld`/`focusWasPlaying`/`focusListener`。
- Service 保留 alias（get/set 转发），**所有现有方法零改动**、行为不变；真机 smoke 确认无回归。
- `focusListener` 注入 `onFocusChange: (Int) -> Unit`（Service 传 `onMultiTrackFocusChange`）。

**线程归属（写进 Coordinator KDoc）**
- `current`/`active`：**主线程专属**（命令 handler/listener/快照 lambda 读写）。
- `io`：唯一跨线程执行者，只跑 `load/loadStream/close`；完成后 `withContext(Main.immediate)` 回填 `current/active`。
- alias 不得在 `io` 线程读写，否则重新引入跨线程可见性问题。

**依赖方向（破循环）**
- Coordinator **不持有** `SnapshotPublisher`；需要推快照时调用注入的 `requestSnapshot: () -> Unit`。
- 装配顺序：`Service → coordinator(注入 requestSnapshot = { snapshotPublisher.request() })`；
  `snapshotPublisher(注入 snapshot = { coordinator.current/active })`。单向、无环。

**3b · 控制与焦点**
- 方法：`handleExit`、`handleSetVolume/ToggleMute/ToggleSolo`、`enter/exitMultiTrackFocus`、`onMultiTrackFocusChange`、`reconcileFacadeToMixer`。
- 注入：`Context`、`Handler`、`singlePlayer` 提供者、`eqHost`、`requestSnapshot: () -> Unit`、`onModeChanged`（**不注入 SnapshotPublisher 实例**）。

**3c · 清 alias + Service 收尾**
- 删除 alias，替换剩余引用，`PlaybackService` 目标 ≤400 行。

**引用点清单（3a 必须同步改）**：
| 位置 | 现写法 | 改后 |
|---|---|---|
| `onCreate` listener | `if (!inMultiTrack) attachSingleEq(player)` | `coordinator.active` |
| `onPositionDiscontinuity` | `if (inMultiTrack && seek) multiTrack?.seekTo(..)` | `coordinator.onFacadeSeek(ms)` |
| `onPlayerCommandRequest` | `if (inMultiTrack)` | `coordinator.active` |
| `handleDebugPos` | `multiTrack?.trackList` | `coordinator.trackList` |
| `pushTracksSnapshot` 回调 | `multiTrack`/`inMultiTrack` | `coordinator.current/active` |
| `eqHost` 构造 | `isInMultiTrack`/`currentMultiTrack` | coordinator 提供 |
| `onIsPlayingChanged`/`onPlaybackStateChanged` | 可能读 `inMultiTrack` | coordinator |

- 构造注入：`Context`、`Handler`、`singlePlayer` 提供者、`onMultiTrackChanged` 回调（供快照）、`EqHost`（多轨 EQ 重挂）。
- **必须保留**：P1-1 的 `multiIo` 串行、`multiLoadPending` 门控（三条音量命令 + play/pause）、P1-B 的 tracks 快照、P2-3 的门面 ENDED 对齐。
- 验收：真机 `inmt → mtvol×30 → exitsmt → inmt` 快速往复；`sepdouble`；焦点丢失/恢复；无 CME/FATAL。
- 预计：Service -300 行（3a 约 -120，3b 约 -120，3c 收尾 -60）。

### Step 4 · `PlayerCommandHandler`

迁移：`onCustomCommand` 的 when 分派、`handleDebugPos`、`dispatchCommand` 辅助。

- **安全边界必须留在 Service**：`controller.uid == Process.myUid()`（L2 第二道门）保留在
  `onCustomCommand` 最外层、委托之前，**不下沉**到 handler；拒绝时仍返回
  `SessionResult(SessionError.ERROR_NOT_SUPPORTED)`，错误码语义不变。
- Service.onCustomCommand 只做「UID 校验 → 委托一行」。
- 验收：`TestCommandService` 的 help 全命令 smoke（load/play/pause/seek/next/prev/repeat/speed/pitch/inmt/exitsmt/mtvol/eq/edge/sepdouble）。
- 预计：Service -60 行。

## 5. 风险与回退

| 风险 | 缓解 |
|---|---|
| EQ 依赖 `audioSessionId` 回调时序，抽类后重挂顺序变 | 构造时注入回调；Step 1 只搬家不改调用点；真机验证单轨↔多轨切换 |
| 多轨加载的 `multiIo` 串行/Pending 门控被破坏 → P1-1/P1-B 回归 | 迁移时逐行对照；补 `multiLoadPending` 测试；真机 30 轮 mtvol + 快速往复 |
| `SnapshotPublisher` 的 `sessionExtras` 合并语义（P2-5）丢失 | 断言 `Bundle(session.sessionExtras)` 写法保留；真机看 UI 进度不闪断 |
| 拆分后 Service 生命周期与 Session 交叉 | Session 不持有 Service 引用，只用 Context + 回调；`onDestroy` 显式 `session.close()` |
| 每步都可能引入音频回归 | 每步真机 smoke + 独立 commit；不行就 revert 该步 |
