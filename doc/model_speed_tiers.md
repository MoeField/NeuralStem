## 三、★ 核心发现：**速度由模型架构决定，与"名字/用途"无关**

按 RTF 把 18 个 UVR 模型排开，**恰好分成 4 个离散簇**，
每簇对应一个 `dim_f`（频谱宽度）配置：

| 簇 | RTF | 模型（体积） | 架构推断 |
|---|---|---|---|
| **A** | **1.00–1.04×** | 9482, KARA, 1_9703, 2_9682, 3_9662（**全部 28MB**） | `dim_f = 2048` |
| **B** | **0.52–0.53×** | Inst_Main, KARA_2（**均 50MB**） | `dim_f ≈ 2560`/中间档 |
| **C** | **0.41–0.42×** | Inst_HQ_4, Inst_HQ_5, Crowd_HQ_1（**均 56MB**） | `dim_f ≈ 2816`/中间档 |
| **D** | **0.34–0.35×** | Voc_FT, Inst_HQ_3, Inst_1/2/3, Inst_HQ_1/2, Main（**全部 64MB**） | `dim_f = 3072` |

> [!IMPORTANT]
> **不是"Inst 系就慢"** —— Inst_HQ_4/5（56MB）比 Inst_HQ_3（64MB）**快 20%**。
> **不是"KARA 就快"** —— KARA（28MB）1.04×，KARA_2（50MB）0.53×。
> **决定速度的唯一变量是模型体积（≈dim_f）**：
> `28MB → 1.0× / 50MB → 0.53× / 56MB → 0.41× / 64MB → 0.35×`。

### 换算公式（经验）

```
RTF ≈ 1.03 × (28MB / 模型体积MB)^1.35
```

验证：`50MB → 1.03×(0.56)^1.35 ≈ 0.47`（实测 0.53，接近）
`64MB → 1.03×(0.4375)^1.35 ≈ 0.34`（实测 0.35）✅

## 七、换设备会怎样

`.memory` 记录（BF00A vs 骁龙 8 Gen3）：

| 引擎 | BF00A (G100) | Gen3 (SM8650) | 加速 |
|---|---|---|---|
| Spleeter 2-stem | 7.9–8.5× | **15–18×** | 1.9× |
| Spleeter 4-stem | 2.22–3.15× | **3.67–6.93×** | 1.65–2.2× |
| Demucs | 0.61–0.82× | **1.35–1.83×** | 2.24× |

⇒ **旗舰机上 Demucs 能到"临界"（1.83×）**，UVR 28MB 系可能到 2×+。
**档位分级必须由每台设备自己的 benchmark 决定**（`DeviceBenchmark` 的设计）。

## 八、复现命令

```bash
ADB=/path/to/adb; S=<serial>; PKG=pub.miku.neuralstem

# 只测已注册的 6 个（设置页/档位用）
adb -s $S shell "run-as $PKG rm -f shared_prefs/device_benchmark.xml"
adb -s $S shell am start -n $PKG/.spike.SpikeActivity --ez benchmark true --es bench_mode long

# 测全部 19 个（含 13 个实验模型）
adb -s $S shell am start -n $PKG/.spike.SpikeActivity --ez benchmark true --ez bench_all true

# 读结果（权威）
adb -s $S shell "run-as $PKG cat shared_prefs/device_benchmark.xml"
```

**实验模型的注册表**：`ModelRegistry.EXPERIMENTAL`（13 个，不进 `ALL`，不参与档位/UI）。
