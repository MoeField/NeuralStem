### ⚠️⚠️ 但有个**法律阻断**：AVS3 解码器不能公开分发

AVS3-P3 解码器的参考实现（`Dreamello/av3a`）不是 MIT/Apache/GPL，而是
【世界超高清视频产业联盟代码共享政策】：

- **第二条**：仅适用于联盟会员，由联盟向**提出申请的会员**许可
- **第六条**：除“有条件转发”外**不能以任何形式转发**
- **第八条**：**不包含专利许可**

⇒ 我们既非会员也非下游客户：**源码与二进制都不能再分发**。

**所以做了这件事**：`avs3dec/` 和两个 UWA `.so` 已**移出 git**（`.gitignore`），
桥改成**纯 dlopen**（不含对方代码 → 可归 MIT）。用户要自己跑：

```bash
./tools/fetch-avs3.sh                        # 从上游拉源码（不进 git）
./gradlew app:assembleDebug -Pwith_ncm=true   # 编出独立的 libavs3self.so
```

详见 **`doc/.memory.md` §8.5** + 仓库根 `README.md` 的「AVS3-P3 支持状态」节。

## 1. 项目是什么

Android 原生「本地 AI 音轨分离播放器」（EE5415 个人项目）：导入单曲 → **本地离线** AI 分离
（人声/伴奏，或 4 轨：人声/鼓/贝斯/其他）→ 多轨同步播放 + 各轨音量/静音/独奏 → 变速变调 + 波形拖动。

- 需求：`doc/guide.md` ｜ 技术栈：Kotlin + Compose(M3) + Media3/ExoPlayer + sherpa-onnx/ONNX
- minSdk 23 / targetSdk 37 ｜ NDK `30.0.16248370` + CMake `4.1.2`

### 6.0 ★ 如何自己跑命令（Agent 工具用法；新对话必读）

> **有 `run_shell_command` 工具就直接跑，别把命令丢给用户手动执行。** 用户侧看到“要批准”
> = 当前 Agent 没被授予该工具/权限，只能退化成“把命令给你跑”。

1. **工具调用**（一次一条命令，不要写多行脚本）：
   ```
   run_shell_command(command="...", description="...",
     directory="/Volumes/SA500/CU_DG_Sem3/AndroidStudioProjects/NeuralStem",
     shell="bash", interactive=false, timeoutMillis=30000)
   ```
2. **adb 不在 PATH**（`adb: command not found`）→ **用变量直调，勿 export**（用户偏好）：
   ```
   ADB=/Volumes/SA500/Library/Android/sdk/platform-tools/adb; S=TLF2609A004328; PKG=pub.miku.neuralstem
   $ADB -s $S shell ...
   ```
   （SDK 根：`/Volumes/SA500/Library/Android/sdk`，同 `local.properties` 的 `sdk.dir`。）
3. **易卡命令加 `timeoutMillis`**（`adb install` / `am start-*` 可能挂起）→ **非阻塞**：
   先发命令，再 `sleep` **轮询**状态（`run-as ls` / `dumpsys`），**不要跑会挂起的阻塞命令**。
4. **优先专用工具**（比 shell 更稳）：读文件 `read_file`、搜代码 `grep`/`code_search`、
   装 App `deploy`、查 maven 版本 `version_lookup`。**禁止**用 `sed`/`cat`/`grep` shell 去改/读文件。
5. 多步时 **多条命令可并行**（不同文件/独立查询），但**构建·测试·设备交互必须串行**。

### 6.2 环境坑（真机）
- **安装后首条命令报 `process is bad`** → `am install` 后进程未就绪：先 `am force-stop` + `am start` 再调命令总线。
- **向私有目录写文件**：`run-as <pkg> sh -c 'cat > ...'` 可能 Permission denied → 改用
  `adb push /data/local/tmp/x` → `run-as <pkg> cp /data/local/tmp/x files/...`。
- **vivo ROM 丢 manifest 广播** → 测试用 `am start-service`（非 broadcast）。
- **vivo/Android16 吞 app 的 logcat** → 用**测试面板屏上日志** / `dumpsys` / 产物取证。
- **vivo 安装弹窗**（坑 52）：`adb install` 卡在 `PackageInterceptActivity` → 可用坐标点
  “已了解风险” + “继续安装”，或用户手点。
- **`adb input tap` 对 Compose 小控件（chip）不稳** → 大目标（底栏/按钮）通常可点；小控件靠手动/命令总线。
- **BF00A 模型需 push 到私有目录**（坑 41）：`run-as <pkg> sh -c 'cat > files/.../x.onnx'`。
- **BF00A 屏幕超时很短**（~30s 就锁屏，截图/UI 通道易失败）→ 先 `svc power stayon true` +
  `settings put system screen_off_timeout 600000`；仍不稳 → 走**非 UI 通道**（`run-as ls` / mtime / `dumpsys`）。
- **删私有目录文件**：`run-as <pkg> rm -f files/waveform-cache/*.bin` **不可靠**（toybox + glob 问题）→
  用 `run-as <pkg> find files/waveform-cache -type f -delete`。
- **`take_screenshot` 工具在 vivo 上可能报 stale focus**（显示 Launcher/StatusBar）→ 改用
  `adb -s <serial> exec-out screencap -p > /tmp/x.png` 取证。
