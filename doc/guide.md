# 个人项目需求文档：AI 音轨分离播放器

> **文档用途**：本文档用于指导本地 AI Agent 辅助开发，定义项目目标、功能边界和技术约束。技术方案部分仅为**建议方向**，非强制指定，Agent 可根据实际调研和测试结果替换为更优方案。

---

## 一、项目愿景

开发一款 **Android 原生音频播放器**，核心能力是：**导入单首歌曲 → 本地 AI 分离音轨 → 用户实时调节各轨音量、播放速度与音高 → 波形上拖拽跳转**。

产品定位为 **“面向音乐学习者和播客听众的 AI 音轨分离播放器”**，用本地算力免费实现 djay Neural Mix 的核心体验，不追求专业 DJ 功能。

---

## 二、功能需求

### P0 — 基础播放（必须完成）

| 编号 | 功能 | 说明 |
|------|------|------|
| F0.1 | 导入音频文件 | 支持从系统文件选择器导入本地音频（mp3 / wav / flac / aac），使用 `Intent.ACTION_OPEN_DOCUMENT` 或 `MediaStore` |
| F0.2 | 播放 / 暂停 | 标准播放控制 |
| F0.3 | 进度跳转 | 拖动进度条跳转到指定位置 |
| F0.4 | 播放状态显示 | 当前时间 / 总时长 / 播放状态 |

### P1 — 波形交互（核心体验）

| 编号 | 功能 | 说明 |
|------|------|------|
| F1.1 | 波形渲染 | 将音频波形渲染为可交互的进度条，替换标准 SeekBar |
| F1.2 | 波形拖动跳转 | 手指拖动波形时实时跳转播放位置，松手后从该位置继续播放 |
| F1.3 | 播放进度指示 | 波形上显示当前播放位置的视觉指示（如颜色区分已播放/未播放区域） |

### P2 — 变速变调（核心差异化）

| 编号 | 功能 | 说明 |
|------|------|------|
| F2.1 | 速度调节 | 支持 0.5x ~ 2.0x 速度调节，**保持音高不变**（变速不变调） |
| F2.2 | 音高调节 | 支持 ±12 半音的音高调节，**保持速度不变**（变调不变速） |
| F2.3 | 实时生效 | 调节过程中播放不中断，参数实时生效 |

### P3 — AI 音轨分离（项目灵魂）

| 编号 | 功能 | 说明 |
|------|------|------|
| F3.1 | 本地音轨分离 | 导入歌曲后，在设备本地进行 AI 推理，分离出多条音轨（至少：人声 / 伴奏；理想：人声 / 鼓 / 贝斯 / 其他） |
| F3.2 | 分离进度显示 | 显示分离进度（进度条或百分比），分离过程中不阻塞UI |
| F3.3 | 分离结果缓存 | 分离后的音轨保存到本地，避免每次播放都重新分离 |
| F3.4 | 离线运行 | 分离过程完全在设备本地完成，不依赖网络 |

### P4 — 多轨混音播放（完整体验）

| 编号 | 功能 | 说明 |
|------|------|------|
| F4.1 | 多轨同步播放 | 分离后的多条音轨同步播放，用户听到的是混合后的效果 |
| F4.2 | 各轨音量独立控制 | 每条音轨有独立的音量滑块，可实时调节（如把人声拉到0，只留伴奏） |
| F4.3 | 静音 / 独奏 | 每轨支持一键静音和一键独奏 |
| F4.4 | 整体控制联动 | 变速、变调、进度跳转对所有音轨同步生效 |

### P5 — UX 打磨（加分项）

| 编号 | 功能 | 说明 |
|------|------|------|
| F5.1 | 各轨波形颜色区分 | 波形上以不同颜色叠加显示各音轨的波形 |
| F5.2 | 横屏适配 | 横屏下布局优化，适合调节操作 |
| F5.3 | 深色模式 | 跟随系统深色模式 |
| F5.4 | 触感反馈 | 关键操作（如分离完成、拖动跳转）提供触感反馈 |
| F5.5 | 桌面小组件 | 显示当前播放曲目，支持播放/暂停（可选） |

## 三、技术约束与建议

> **重要说明**：以下为建议方向，Agent 应在开发前进行技术调研，若发现更优方案（性能更好、集成更简单、社区更活跃），可替换并在代码注释或文档中说明理由。

### 3.1 平台约束（硬性）

- **平台**：Android 原生开发
- **语言**：Kotlin
- **最低 API Level**：21（Android 5.0）
- **目标 API Level**：33 或以上
- **开发环境**：Android Studio
- **构建工具**：Gradle（Kotlin DSL）

### 3.2 音频播放（建议方向）

| 方案 | 说明 |
|------|------|
| **ExoPlayer（Media3）** | 推荐首选。支持 `AudioProcessor` 链、`PlaybackParameters`、多实例、`ClippingConfiguration` 等 |
| MediaPlayer | 备选。API 简单但扩展性差，不支持自定义 AudioProcessor |
| AudioTrack + 自研解码 | 仅在需要极致控制时考虑，工作量大 |

**关键需求**：必须支持自定义 `AudioProcessor` 链，以便接入时间伸缩处理。

### 3.3 时间伸缩 / 变速变调（建议方向）

| 方案 | 说明 |
|------|------|
| **SonicAudioProcessor** | ExoPlayer 内置，基于 Sonic 库，支持独立调节速度和音高，集成成本最低 |
| Rubber Band | 音质更好但集成复杂，有 Android 移植版本 |
| SoundTouch | 老牌库，有 NDK 移植方案 |
| Superpowered | 商业库，性能极佳但需付费 |

**关键需求**：速度和音高必须能**独立调节**，互不干扰。

### 3.4 AI 音轨分离（建议方向）

| 方案 | 说明 |
|------|------|
| **Spleeter TFLite** | 推荐调研方向。Deezer 开源，有 2-stem / 4-stem / 5-stem 模型，社区有 Android 移植案例 |
| Demucs（Mobile） | 音质更优，但模型更大，移动端部署难度更高 |
| Open-Unmix | 轻量级，有 TFLite 转换可能 |
| 其他 | Agent 可自行调研更适合移动端的模型 |

**关键需求**：
- 模型必须在设备本地运行（TFLite / ONNX Runtime / NNAPI）
- 推理时间在主流中端设备上不超过 60 秒（4分钟歌曲）
- 输出格式为独立音轨文件（WAV / PCM），便于后续多轨播放

### 3.5 波形渲染（建议方向）

| 方案 | 说明 |
|------|------|
| **WaveformSeekBar** | 成熟库，直接替换 SeekBar，支持拖动回调 |
| Amplituda | 波形数据提取库，可从 File / Uri / 资源生成波形样本 |
| 自绘 Canvas | 完全自定义，工作量较大但可控性最强 |

**关键需求**：波形需支持实时拖动跳转，且拖动过程中播放位置同步更新。

### 3.6 多轨同步播放（架构建议）

- **方案 A**：多个 ExoPlayer 实例，每个音轨一个，共享同一套控制指令（play / pause / seek / speed / pitch）
- **方案 B**：单 ExoPlayer 实例 + 自定义 `AudioProcessor` 在 PCM 层混音
- **方案 C**：`AudioTrack` 多实例 + 自研混音器

**关键需求**：seek 后各轨必须严格对齐，不能出现可感知的相位偏差。

## 四、非功能性需求

| 编号 | 需求 | 说明 |
|------|------|------|
| N1 | 离线优先 | 核心功能（播放、分离、调节）完全离线可用 |
| N2 | 内存安全 | 4条WAV同时加载 + 模型驻留，需避免 OOM；必要时使用流式加载或分块处理 |
| N3 | 音频焦点 | 来电或其他应用抢占音频焦点时，优雅暂停并在恢复后继续 |
| N4 | 后台播放 | 切后台后继续播放，使用 `Foreground Service` + 媒体通知 |
| N5 | 分离任务管理 | 分离任务使用 `WorkManager` 或 `Foreground Service`，支持取消和进度回调 |
| N6 | 设备兼容性 | 在低端设备上降级处理（如降低波形分辨率、使用更小的模型） |
| N7 | 代码可读性 | 关键模块需有注释，架构清晰，便于后续维护和报告撰写 |

## 五、验收标准

### 5.1 功能验收

- [ ] 能导入本地音频文件并播放
- [ ] 波形正确渲染，拖动波形能跳转播放位置
- [ ] 速度调节 0.5x ~ 2.0x，音高不变
- [ ] 音高调节 ±12 半音，速度不变
- [ ] 能对导入歌曲进行本地 AI 分离，输出至少 2 条音轨
- [ ] 分离后的音轨能同步播放，各轨音量可独立调节
- [ ] 整体流程无崩溃，无明显卡顿

### 5.2 交付物

- [ ] 可运行的 APK 文件
- [ ] 完整源代码（Kotlin）
- [ ] 简短的使用说明 / README
- [ ] 演示视频（用于个人项目展示）

## 六、开发阶段建议

| 阶段 | 内容 | 优先级 |
|------|------|--------|
| **Phase 1** | 单轨播放器 + 标准 SeekBar | P0 |
| **Phase 2** | 波形渲染 + 拖动跳转 | P1 |
| **Phase 3** | 变速变调（SonicAudioProcessor） | P2 |
| **Phase 4** | TFLite 音轨分离实验（单独验证） | P3 |
| **Phase 5** | 多轨同步播放 + 各轨音量控制 | P4 |
| **Phase 6** | UX 打磨 + 横屏 + 深色模式 | P5 |

**建议**：Phase 4 的分离实验可以提前单独验证，确认模型在目标设备上的推理时间和内存占用，再决定是否集成到主流程中。

## 八、给 Agent 的备注

1. **技术选型灵活**：以上建议方案均可替换，但需在代码注释或独立文档中说明替换理由。
2. **优先验证核心风险**：Phase 4（TFLite 分离）是最大技术风险，建议尽早做技术验证（Spike）。
3. **保持模块化**：音频播放、时间伸缩、音轨分离、波形渲染应为独立模块，便于单独测试和替换。
4. **注意 Android 版本兼容**：最低 API 21，需处理不同版本间的 API 差异（如 `PlaybackParams` 在 API 23+ 才可用）。
5. **性能优先**：低端设备上的表现是项目成败的关键，需在开发过程中持续在真机测试。
6. **报告呼应**：代码中可适当注释与 djay 分析报告的关联点（如“本地算力免费实现 Neural Mix 核心体验”），便于后续撰写个人项目报告。
