- ✅ **分离开关关→再开无法恢复**（要重跑分离）—— `8e9c587` 已修
- ⬜ **实时分离的“实时”** —— 未做（见上 5）

### ★ 已确认缺陷：Demucs 完整歌 Java 堆 OOM（BF00A + Gen3 均复现）

- **现象**：Demucs 跑完整歌（5:14）→ OOM 崩溃（BF00A 8s；Gen3 亦同）。
- **根因（Gen3 native crash dump 实证）**：
  - `JNI SetFloatArrayRegion ... OutOfMemoryError: allocate 44040208 byte ... target/growth 536870912`
  - `DemucsEstimator.nativeEstimate` 一次性回 `float[][]`（每块 44MB）+
    `DemucsSeparator.acc = Array(4){Array(2){FloatArray(total)}}`（**5:14 = 443MB**）
  - ⇒ **两处大数据进 Java 堆**（**上限 512MB，与设备物理 RAM 无关**；`largeHeap` 也是 512）。
- **修复方向**：大缓冲**留 native**（direct ByteBuffer / JNI）或 **流式落盘**（同 Spleeter4）。
- **状态**：⬜ **待定**（用户倾向“切块处理”）。

### ★ 待观察（不占精力；若再遇到再查）：2-stem “回声/疑似偏移”

- **现象**：用户某首歌 2-stem 听到“回声感”（关掉一轨消失）→ 疑两轨错开。
- **用户复现**：**其他几首歌复现失败**（非系统性问题）。
- **量化（互相关）**：该曲 voc/acc **整体 lag = 0**（长度也相等）；局部 lag≠0 的窗口
  **ncc 均 ≤0.22（低相干）** → 属坑 38/39 的“低相关窗伪影”，非真偏移。⇒ 更可能是
  **Spleeter 渗漏**（同一人声成分出现在两轨 → 叠加有梳状/回声感），属音质范畴。
- **决策**：**先不管**（复现失败 + 无稳定病征 + 指向音质非 bug），记录待观察。
